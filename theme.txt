Redesign my existing website UI based on the attached screenshots, while keeping ALL existing functionality, routes, API calls, backend logic, RAG logic, state management, and uploaded-data behavior intact.

The project is a RAG-based study assistant called “Deadline Guardian”.

IMPORTANT:
Do not rebuild the application from scratch.
Do not remove existing functionality.
Only improve the visual design, UX, loading states, and presentation.
Use the current codebase and adapt the existing components.

========================
DESIGN DIRECTION
========================

Transform the current dark purple/neon UI into a BRUTALIST editorial-style interface.

Primary visual identity:
- Warm peach background
- Dark forest green as the main accent
- Pale/light green for secondary surfaces
- Near-black text and borders
- Brutalist thick borders
- Large hard offset shadows
- Sharp rectangular cards
- Very limited border radius; preferably 0–4px
- Bold condensed/monospace-style typography for headings
- Clean readable font for body text
- Chunky icons
- Slightly imperfect/blocky visual elements
- Pixel/grid decorative elements in the background
- Strong visual hierarchy
- No glassmorphism
- No excessive gradients
- No generic modern SaaS look
- No excessive rounded cards
- No floating purple/neon elements

The result should feel like:
“academic productivity tool + brutalist editorial website + modern RAG interface”

Color direction:
- Background: warm peach / light peach
- Primary: deep forest green
- Secondary: muted sage/light green
- Text: almost black
- Borders: almost black
- Status/success: green
- Warning/loading: peach/orange
- Avoid purple as the dominant UI color

========================
RAG PIPELINE LOADING EXPERIENCE
========================

THIS IS THE MOST IMPORTANT CHANGE.

Because this is a RAG application, do not use a generic spinner or vague “Loading...” message.

Whenever the backend is processing a RAG request, display a large brutalist processing panel.

Title:

“RAG PIPELINE IN WORK...”

Subtitle:

“Processing your query and finding the most relevant information.”

Show four explicit pipeline stages:

1. UNDERSTAND QUERY
   “Rewriting & extracting key concepts...”

2. RETRIEVE CONTEXT
   “Searching relevant chunks in your notes...”

3. GENERATE ANSWER
   “Using LLM with retrieved context...”

4. FINALISING
   “Formatting answer with sources...”

Represent the stages horizontally using chunky icons and connected lines.

The currently active stage should be visually highlighted.

Completed stages:
- forest green
- check mark
- solid styling

Current stage:
- peach/orange highlight
- animated but brutalist
- clear visual emphasis

Upcoming stages:
- muted/pale green
- lower contrast

Add a thick progress bar underneath.

Example:

“Searching relevant content... (3/4)”

The progress should correspond to REAL application state whenever possible.

Do NOT simply create a fake 4-second animation.

If the backend already exposes loading states/events, connect the UI to them.

If the current backend does not expose granular RAG stages, create a clean frontend abstraction for these states:

UNDERSTAND_QUERY
RETRIEVE_CONTEXT
GENERATE_ANSWER
FINALISING
COMPLETE
ERROR

Map the existing RAG request lifecycle into these states without changing the actual backend behavior.

The loader must disappear automatically when the answer is ready or an error occurs.

For errors, replace the pipeline success styling with a clear brutalist error state.
